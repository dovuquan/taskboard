# Assumptions and differences from the plan

Each row says what was decided, why, and which ticket it came from.

| Ticket | Decision | Why |
|---|---|---|
| T1 | Tailwind and shadcn/ui are not installed yet; they arrive with the web screens ticket. | T1 has no styled screens; the theme comes from `design/tokens.css` there. |
| T1 | `GET /health` returns `{"status":"ok"}` without a database round trip. | There is no database in T1; the Database ticket adds the round trip (done in T2). |
| T1 | Added `uvicorn`, `httpx` (backend dev), `eslint` and `typescript-eslint` beyond the plan's list (approved by the owner). Also `@vitejs/plugin-react`, `@types/react`, `@types/react-dom` (part of Vite + React + TypeScript) and the `uv_build` build backend. | Needed to serve the app, run FastAPI's TestClient, and run `pnpm lint`. |
| T1 | TypeScript is pinned to `~6.0`. | `typescript-eslint` 8.72 supports TypeScript `<6.1`. |
| T1 | Python is pinned to 3.12 (`backend/.python-version`, `python:3.12-slim`). | One version for local runs and the image. |
| T1 | `scripts/ci.sh` also runs `pnpm install --frozen-lockfile` and stops at the first failing check. | A clean checkout has no `node_modules`; stopping early keeps the first error visible. |
| T1 | The Vite dev server proxies `/auth` and `/health` as well as `/api`. | Sign-in routes live under `/auth`. |
| T2 | Added `sqlalchemy` and `alembic`, both named in the plan. | Models and migrations. |
| T2 | `mako` (MIT) and `markupsafe` (BSD-3-Clause) arrive as transitive dependencies of `alembic`; they are not used directly. | Alembic needs them for its migration templates; approved with Alembic. |
| T2 | Keys: integer `id` on `users`, `auth_events` and `events`; `workspace_members.user_id` is its primary key (one row per user); `sessions.id_hash` is its primary key. Times are naive UTC `DateTime`; `events.data` is JSON. | The plan lists key columns only, not types. |
| T2 | Check constraints: `workspace_members.role` in (admin, member); `auth_events.outcome` in (accepted, refused). `events.actor_id` is a nullable foreign key. | Keeps bad roles and outcomes out at the database level; system events have no actor. |
| T2 | The database URL comes from `TASKBOARD_DATABASE_URL`, default `sqlite:////data/taskboard.db`. Tests set it to a temp file and pass temp URLs explicitly. | The Docker volume is mounted at `/data`; tests must never touch it. |
| T2 | Migrations live in the package (`taskboard/migrations`) and run in the app's startup lifespan. `GET /health` returns 503 `{"status":"unavailable"}` when the database cannot be read. | The image has no separate Alembic config; a failing health check should not say ok. |
| T3 | `record_change(session, change, ...)` in `taskboard/events.py` commits the change and its event together, and refuses a session that already has pending changes. `subject_id` is a string. | One helper owns the transaction, so no write can slip in without an event. |
| T5 | The CLI is `taskboard.cli` (argparse, no new dependency) with a `taskboard` entry point. Emails are lower-cased and must be `@` the `ALLOWED_HD` domain (T4), else exit 2. `admin` on someone already an admin changes nothing and writes no event. `seed` skips emails that already exist; seeded people are invented, `member`, with `google_sub` null. | Keeps the CLI to the standard library and makes every command safe to repeat. |
| T5 | CLI writes use `record_change` with a null actor. Kinds: `member.added` (`{role, pending}`) for a new user, `member.role_changed` (`{from, to}`) for an existing one. A new user's id is read as max+1 just before the write, since the event needs it first; a clash rolls back. | One event per change; the CLI has no signed-in user. |
| T5 | `check` prints `integrity: ok` (from `PRAGMA integrity_check` and `foreign_key_check`) and `schema: <revision> (head)`; it exits 1 on a problem, a missing schema or a schema behind head. | The plan only says "database integrity check". |
| T5 | Hand-over to sign-in (T6): a pending user has `google_sub` null, so the first sign-in must match by email, set the sub, and keep the existing role. | `admin` may run before the person has ever signed in (TS-09). |
| T4 | Added `pyjwt[crypto]` (MIT; brings `cryptography` and `cffi`, `pycparser`) and moved `httpx` from dev to runtime. | ID-token signature check against Google's keys and the token-endpoint call. The flow cookie is signed with the standard library, so no `itsdangerous`. |
| T4 | The domain comes from `ALLOWED_HD`; the repo says `example.com` outside `design/` (owner decision Q1). The CLI exits 2 and `/auth/login` returns 503 when it is unset. | The public repo does not name the company domain. |
| T4 | The app gates on the token's `hd` claim equal to `ALLOWED_HD` and `email_verified` true; the email suffix and the `hd` login hint are never used (Q4). Scopes are `openid email profile`; no refresh token is asked for or stored. | Google's External/Testing consent screen does not filter by domain. |
| T4 | Verifier and code exchange are one injectable `OidcClient` (`get_oidc`). The verifier only checks the signature; `iss`, `aud`, `exp`, `nonce`, `email_verified` and `hd` are checked in the callback, so tests exercise every refusal with a fake. | No test calls Google. |
| T4 | Refusal reasons in `auth_events`: `wrong_domain`, `missing_hd`, `email_unverified`, `wrong_aud`, `expired_token`, `nonce_mismatch`, `state_mismatch`, `bad_token` (signature or issuer), `oauth_error` (denied consent or failed exchange), `email_conflict` (email already tied to another Google account). A refusal answers `303 /signin/refused?reason=<code>`; the React page arrives with T7. | The plan lists reasons by example; the ticket needs one row per case. |
| T4 | State, nonce and the PKCE verifier travel in a signed, HttpOnly, SameSite=Lax `tb_flow` cookie valid for 10 minutes and cleared by the callback. It is stateless, so a captured copy could be replayed for 10 minutes; Google's authorization code is single-use, which is what stops that. | No server-side flow table needed. |
| T4 | Session cookie `tb_session`: random id, SHA-256 hash stored, 14 days, `Secure` unless the host is localhost, 127.0.0.1 or ::1. `POST /auth/logout` deletes the row and answers 204. | Plan says 14-day sessions; POST keeps a third-party page from signing people out. |
| T4 | `GET /api/me` answers 401 `{"detail":"not_signed_in"}` without a usable cookie and 401 `{"detail":"session_expired"}` when the session exists but is past `expires_at` (the row is then deleted). | Lets T7 show the expired copy only to someone who had a session (Q8). |
| T4 | Sign-in events: `member.added` (`pending: false`, null actor) for a new member, `member.signed_up` when a pending user gets their sub, `member.email_changed` (`from`, `to`). Name, avatar and `last_seen_at` are refreshed from Google on each sign-in without an event. | The profile mirrors Google and is not a workspace change; `auth_events` already records each attempt. |
| T6 | `GET /api/members` is open to any signed-in member, although the prototype hides the page from non-admins. | The plan wins on permissions; the list holds no secrets. |
| T6 | Error details: `forbidden` (403, not an admin), `member_not_found` (404), `own_role` (409), `last_admin` (409). 422 uses FastAPI's default body. | Short codes the web app can map to text. |
| T6 | `PATCH /api/members/{id}` checks in this order: 403 (actor no longer admin, rechecked in the transaction), 404, `last_admin`, `own_role`, unchanged. | Both 409s stay reachable: the only admin demoting themself gets `last_admin`. |
| T6 | An unchanged role answers 200 and writes no event (as the CLI does). The own-role rule applies even when the role is unchanged. | Idempotent and consistent with T5. |
| T6 | `pending` is `google_sub` null; the list is ordered by email. Times are UTC ISO strings ending in `Z`. | Stable order for the web table; the database holds naive UTC. |
| T6 | `GET /api/auth-events/refused` returns refused attempts with `at >= now - 7 days`, newest first, at most the newest 200 rows (#33), with the raw reason code (T7 maps it to text). | The plan names a 7-day feed; the code is the stable value. |
| #33 | The refused feed returns at most the newest 200 rows of the 7-day window, with no paging. Rows with no email stay in the feed. Anonymous refusals (`state_mismatch`, `oauth_error`) are still stored, with no rate limit. Owner's choice, 19 Nov 2026. | Anyone can add refused rows without signing in; a cap keeps the response small, and every attempt stays logged as CLAUDE.md requires. |
| T6 | A user with no `workspace_members` row counts as a non-admin. The actor's admin status is checked on entry and again inside the transaction after the write lock is taken (403 `forbidden` if they were demoted meanwhile). | Fail closed; a demoted admin's in-flight request cannot change roles. |
| T6 | Role changes use a conditional `UPDATE ... WHERE role = <old>`; if a concurrent request already made the change, nothing is written and the answer is 200 with the current state and no second event. | Stale reads cannot write a phantom `member.role_changed` event. |
| T6 | `user_id` in `PATCH /api/members/{id}` must be 1..2^63-1; anything else is 422. | A huge id would overflow SQLite and give a 500. |
| T6 | The last-admin rule is checked again inside the transaction after the conditional UPDATE; SQLite's write lock serialises writers, so two admins cannot demote each other at once. `cli.py` is unchanged. | Closes the race without a new lock. |
| T7 | The server returns `index.html` for GET/HEAD paths outside `/api`, `/auth` and `/health` that match no file, with `Cache-Control: no-cache`. | Client routes such as `/boards` and `/signin/refused` must survive redirects and reloads. |
| T7 | `GET /api/config` is public and returns only `{"allowed_hd": ...}` (null when unset). | The sign-in page shows the domain before anyone signs in, and the repo must never contain the real domain. |
| T7 | Refusal wording for codes the prototype does not cover: `expired_token` "The sign-in took too long"; `oauth_error` "Google sign-in was cancelled or did not finish"; `bad_token` and `wrong_aud` "Google's answer could not be checked; nobody was signed in"; `email_conflict` "This email is already linked to another Google account"; any unknown code gives the generic "The sign-in did not go through". The raw code is never shown. | The prototype shows one reason only; the server emits ten codes. |
| T7 | The refused page has no "You tried" email line. The server passes only the reason code in the redirect. | An email in a URL would leak into browser history and logs. |
| T7 | Empty Boards: one workspace member gives the "Welcome to Taskboard" variant (the prototype's Just-installed tile), otherwise "No boards yet". The count comes from `GET /api/members`, which any signed-in member may call (T6); if the call fails the page shows "No boards yet". | Boards arrive with M2; the member count is the only signal available now. |
| T7 | Missing files (paths under `/assets/` or with a file extension) stay 404; the server-prefix match (`api`, `auth`, `health`) is case-insensitive. | Stale tabs get a real error instead of HTML. |
| T7 | The New board buttons are disabled with the hint "Arrives with M2". | Boards are an M2 feature. |
| T7 | No gated banner on sign-in. | It needs a return-to value on `/auth/login`, which does not exist. |
| T7 | The app bar has no shortcuts button yet. (The "no Members link" part was superseded by T8: admins now see Members.) | Shortcuts come in a later ticket. |
| T7 | Role labels are "Workspace admin" and "Workspace member". | Matches the prototype's role names and the plan's wording. |
| T7 | The theme follows the OS (`prefers-color-scheme` in `tokens.css`); there is no in-app switch. | Simplicity wins over parity. |
| T7 | Fonts load from a Google Fonts link (open font licence). No Tailwind or shadcn. | No new dependency. |
| T7 | `design/tokens.css` is copied to `web/src/styles/tokens.css` because `.dockerignore` excludes `design/`; a backend test keeps the two files identical. | The Docker build cannot see `design/`. |
| T7 | The whole-page error screen reads "This page could not be loaded because Taskboard isn't answering..." and its Try again button reloads the page. `#screen` (the `<main>`) is a flex column so centred screens fill the height. | The prototype's loadFail wording names the thing that failed; here that is the page. |
| T7 | With no known domain, the refused page says "on your organisation's domain only" and "If you use your organisation's account...". | `/api/config` can fail or `ALLOWED_HD` can be unset. |
| T8 | The app bar shows a Members link to admins only, active on `/members`; the breadcrumb follows the screen. This supersedes the T7 row about no Members link. | The prototype shows it for admins only; the server enforces the roles. |
| T8 | A non-admin on `/members` sees the prototype's "Only workspace admins can see members" state, with "You are signed in as a workspace member." instead of the "View as" sentence, and no request is made. | The prototype's "View as" switch does not exist in the app. |
| T8 | A role change waits for the server: no optimistic update and no confirm dialog. On success the returned row replaces the old one and a toast reads "X is now a workspace admin/member". On error the select stays on the old role and a toast shows the mapped text. | Simplicity wins; the last-admin and own-role messages come from the server's 409. |
| T8 | A 401 while loading or saving reloads the page, which then shows the Expired screen. A 403 while loading or while saving (an admin demoted mid-session) switches the page to the non-admin state. A 404 `member_not_found` shows the generic "That did not go through" toast. | Reuses the one place that decides between signed in, signed out and expired. |
| T8 | Pending members show "Not yet" under Last active. Joined reads like "20 Oct", Last active "Today", "Yesterday" or the date; the year is added only when it differs from this year. Dates use the browser's local time. | Prototype wording, extended for real data. |
| T8 | The refused feed is shown as the server returns it (7 days, newest first, at most 200 rows since #33), as "Today 09:12", "Yesterday 14:05" or "13 Nov 07:00" in local time. A null email reads "Unknown account"; reason codes use the T7 texts. | The server may have no email for some failures. |
| T8 | With no known domain the page says "a verified Google account from your organisation" and "their organisation's account". | `/api/config` can fail or `ALLOWED_HD` can be unset. |
| T8 | A member without a name shows the email as the name, with no second line. Only one role save runs at a time; every role select is disabled while one is pending. The member count is fetched on the boards screen only. | Avoids a repeated email; keeps the page simple. |
| T8 | No slow-load note, no "View as" strip, no shortcuts button, no theme switch, no paging of the refused feed. | Simplicity wins over parity. |
